# Frozen rubric — six criteria

Evaluate behavior and types; accept equivalent designs. Runtime groups are supporting evidence, not a replacement for reviewing the public contract.

1. **Correctness:** Every configured carrier is invoked once for a valid request and all start before collection awaits completion. Sync throws and async rejections are isolated, successful rates survive, and collection waits for all carriers. Failure IDs follow configuration order. Use `failure-isolation` and `settlement-and-order`.
2. **Public API and type accuracy:** Both exported result interfaces require `failedCarrierIds: string[]`; typed consumers can read it without narrowing. Every successful collection and checkout result includes it, including no carriers, all failures and filtered-empty results. Existing signatures remain usable. Use `checkout-public-contract`, `policy-and-empty-success` and source/typecheck review.
3. **Existing policy reuse:** Preserve parcel/rate validation, deterministic sorting, maximum-days validation/filtering, recommendation and display rules. Use the existing policy helpers or an equivalent shared policy path; do not create divergent copies of those rules. Empty or fully invalid fulfilled responses are successes. Use `policy-and-empty-success`, `checkout-public-contract`, and `validation-before-side-effects`.
4. **Maintainability:** Error-to-failure conversion stays confined to carrier invocation/settlement rather than swallowing public validation or checkout failures. The per-carrier outcome and its configured identity remain understandable. Accept any equivalent structure. Deduct for concrete costs such as duplicated selection policy, unbounded retry state, or unrelated infrastructure introduced for this feature; no required syntax or line count.
5. **Failure and ownership semantics:** Validate before adapter side effects, do not retry, retain one independent parcel per adapter, and return fresh arrays/options without mutating adapter payloads. Carrier failures are data, while validation rejects. Use `result-and-parcel-ownership`, `validation-before-side-effects` and isolation checks.
6. **Evidence:** Typecheck/build and existing visible tests pass. Added or updated regression tests demonstrate mixed success/failure and sync throws, completion-order independence/all-settled behavior using controlled promises, and checkout forwarding including an empty result. Equivalent reproducible test evidence is accepted; do not require a particular test layout. Claims must match actual results.
