# Staff training desk

Private application for an internal training coordinator and employee portal. Target runtime is Node 22 ESM. There are no runtime dependencies. Use `npm run typecheck`, `npm run build`, and `npm test` after installing the declared development tooling.

`model.ts` owns directory email normalization and domain error codes. `store.ts` owns per-desk mutable session state. `desk.ts` is the trusted in-process application API. `portal.ts` contains the current JSON submission caller and attendance export caller. Seeds come from the coordinator's typed configuration, not arbitrary JSON; their business constraints are checked at desk construction. Submission JSON is untrusted and is validated at the portal boundary. Unknown extra JSON fields are ignored today.

Employees enroll in a session with a fixed positive seat capacity. Emails are trimmed and lowercased, then checked for a basic email shape. Duplicate enrollment is rejected. Cancellation removes an existing enrollment. Attendance contains confirmed employees in enrollment order.

Enrollment accepts an optional `{ waitlist: boolean }`: a full session queues opt-ins in join order and rejects other requests with FULL. Rosters include all enrollment statuses and `admissionsOpen`, which starts true. `setAdmissions(sessionId, open)` pauses or resumes admissions. While paused, enrollment fails with ADMISSIONS_CLOSED before email or duplicate checks; cancellation remains available without promotion. Reopening offers available seats to the waiting list in FIFO order. Open-session cancellation of confirmed or offered entries also offers released seats to waiting employees. Offers reserve capacity until accepted, declined or cancelled; they do not expire. Only confirmed employees appear in attendance. `acceptOffer` confirms an offered entry even while admissions are paused; `declineOffer` removes it and offers the released seat only while admissions are open. Both normalize email, check session existence first, and fail with NOT_ENROLLED for missing entries or NOT_OFFERED for other statuses. Portal submissions validate the optional boolean `waitlist` field and return the resulting enrollment status.

Domain failures throw `DeskError` with stable `code` values: INVALID_SESSION, DUPLICATE_SESSION, NOT_FOUND, INVALID_EMAIL, ALREADY_ENROLLED, FULL, NOT_ENROLLED, NOT_OFFERED, ADMISSIONS_CLOSED. Portal submission translates domain errors into failure replies; malformed JSON shapes produce BAD_REQUEST. Unexpected programming errors propagate. For desk operations, session existence is checked before email validation. Failed operations do not change state. Each desk owns its data; seeds, returned enrollments, rosters and attendance arrays may be mutated by callers without altering stored data.

The desk and portal exports are used only by this application and its tests; there are no external package consumers. Tests execute built JavaScript from dist. Keep the attendance export and portal submission consistent with the application rules.
